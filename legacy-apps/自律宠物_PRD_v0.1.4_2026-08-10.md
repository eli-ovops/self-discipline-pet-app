## 0. 一屏产品定义

### 0.1 一句话核心

**一款通过宠物共同成长，帮助用户减少社媒干扰的自律效率 App。**

宠物不是为了提高 App 打开次数而设置的游戏奖励，而是用户自律承诺的具象化伙伴。用户使用产品的根本原因不是养宠物，而是借助宠物陪伴，让自己更容易开始、坚持，并在必要使用或中断后返回原任务。

### 0.2 Product Thesis

我们认为：

1. 用户通常知道自己应该学习或工作，真正困难发生在准备打开社媒的冲动瞬间；
2. 系统限制可以阻止一次点击，但单纯的工具提示容易被忽略或关闭；
3. 一只与用户共同积累真实专注记录的宠物，可能成为冲动瞬间的情感连接点；
4. 宠物必须改善“开始、坚持、返回”至少一个行为，而不能只是让普通限制器更可爱；
5. 第一轮没有观察到宠物增量时，只允许进行一次有边界的体验优化并重新验证；仍没有具体行为证据，则停止扩大宠物内容投入。

本版暂不设置普通限制器 A/B 对照组。宠物增量先通过具体行为访谈、返回率、主动复用及实际使用轨迹验证；是否增加正式对照组在行为验证方案冻结时再决定。

### 0.3 首批用户与长期顺序

- **首批验证用户：**正在准备考试、主要使用电脑学习、但经常被 iPhone 上 Reddit、TikTok 等社媒打断的大学生和研究生；
- **首批市场：**英语市场；产品同时支持英语和中文，系统语言自动选择并允许手动切换；
- **首批自然招募入口：**Reddit 与 TikTok，只做后续经授权的招募；本 PRD 不授权外联；
- **第二顺位人群：**自由职业者；只有学生场景成立后才单独验证，不能直接继承学生结论；
- 不以 ADHD、成瘾治疗或任何医疗效果作为定位和招募承诺。

### 0.4 核心闭环

```text
设定唯一目标
  → 宠物陪伴目标
  → 系统限制用户选择的分心 App
  → 完成专注，或在必要使用/中断后返回
  → 记录共同完成
  → 选择一次短互动
```

必要使用支线：

```text
点击受限 App
  → Shield 显示返回/申请入口
  → 跳转主 App
  → 看见原目标、受限范围和提醒规则
  → 选择预设原因或填写自定义原因
  → 解除本次专注中用户选择的全部受限 App
  → 10 分钟温和召回，30 分钟提示超时后果
      → 用户在 60 分钟内主动返回
          → 全部受限 App 重新受限
          → 继续原目标剩余时间
      → 60 分钟仍未返回
          → 结束本次专注且无奖励
          → 已解除的 App 保持解除
```

上面是 **P0 要验证的理想流程**，不是已经证实的 Apple 能力。“全部受限 App”仅指本次专注中用户主动选择的限制集合，不是设备上的全部 App。若无法可靠解除该集合、用户返回后无法重新限制全部对象、状态显示与真实 Shield 不一致或必须依赖私有 API，P0 直接失败，不得静默降级。

### 0.5 P1 产品承诺

- 原生 iOS App；
- 猫、狗、兔三选一，每个用户同时只有一只当前宠物；
- 三只宠物拥有不同性格和完整、等价的核心动作资产；
- 用户可使用固定默认名或自定义命名，认领后仅允许再改名一次；
- 默认只有一次更换宠物机会；
- 新宠好感度从 0 开始，原宠好感度永久冻结并进入“共同回忆”；
- 一次完成可选择喂食、洗澡或玩耍一次，三类互动奖励相同、不累积；
- P1 免费，不展示商店、订阅、广告、抽卡或购买入口；
- P1 不依赖账号、服务器、云同步或第三方分析。

### 0.6 北极星指标

**用户在计划学习时段内减少对所选分心 App 的使用，并愿意在下一次真实学习任务中主动再次开启保护。**

P0 不要求记录 Shield 展示次数或“直接返回”次数，只验证核心限制闭环。第一版仅记录产品自身明确发生的申请、返回、完成、放弃和超时事件；更细的行为测量等待真实用户使用后再决定。App 打开次数、宠物点击次数、截图喜欢度和动画播放次数都不是北极星指标。

## 1. Problem Statement

### 1.1 用户问题

准备考试的学生无法永久封锁手机：验证码、必要消息、课程资料和紧急事项仍可能要求使用手机。但“只看一下 Reddit/TikTok”又容易变成无目的浏览。

现有两端方案各有缺陷：

- 纯系统提醒过于工具化，容易被无意识忽略；
- 强制封锁误伤必要使用后，用户容易撤销权限或卸载；
- 普通番茄钟记录时间，却不一定在用户准备打开社媒的瞬间产生停顿；
- 过度游戏化、连续签到和宠物受苦会制造内疚与新的 App 沉迷。

用户需要：

1. 开始前写下本次唯一目标；
2. 自己选择本次要限制和临时豁免的 App；
3. 冲动打开社媒时获得一次有意义的停顿；
4. 必要使用时保有自主权，但原因、时间和返回目标可见；
5. 中断后可以回来，而不是被判失败；
6. 通过一只长期伙伴看到共同完成记录，而不是为了签到养宠物。

### 1.2 产品机会

传统工具强调“我阻止你”“我给你计时”。自律宠物强调：

> **我知道你要完成什么，并陪你一次次回到它。**

宠物承担四个产品职责：

1. 把本次目标持续具象化；
2. 在 Shield、批准使用、提醒和返回环节保持一致的情感语义；
3. 把真实完成记录为共同经历；
4. 在中断后提供无羞辱的重新开始入口。

宠物不承担：信息流、聊天机器人、持续剧情、饥饿惩罚、每日签到或无限收藏。

## 2. First-principles Review

### 2.1 必要前提

1. 根目标是减少数字干扰并完成任务，不是提高养宠时长；
2. 用户必须保有停止、放弃和删除数据的控制权；
3. 必要使用时间不得伪装成专注时间；
4. “无申请加分”只能证明本次没有通过产品申请通行，不能声称用户没有碰手机或其他设备；
5. 宠物关系不能依赖受苦、衰减、死亡、责备或连续清零；
6. 限制状态必须来自 Apple 官方框架的真实结果，不能由 UI 自行推测；
7. 技术可行、视觉可爱和用户愿意付费是三条独立证据链。

### 2.2 红队攻击与阻断

| 攻击或误用 | 风险 | 当前阻断 | 残余风险与验证 |
|---|---|---|---|
| 用户每次输入一个字符申请通行 | 原因流程变成无意义点击 | 允许任意输入，但提交前必须看见原目标、解除范围和提醒规则 | 申请次数不限；必须验证这次停顿是否仍改变行为 |
| 一次申请解除全部已选受限 App | 用户可借一个理由进入其他已受限社媒 | 10/30/60 分钟通行窗口、统一记录、无申请加分失效 | 这是有意采用的低摩擦设计，行为验证必须检查是否被系统性滥用 |
| 用户忽略提醒继续使用 | 一次必要使用演变为长时间偏航 | 10 分钟召回、30 分钟警示、60 分钟结束本次专注且无奖励 | 60 分钟后 App 按产品决定保持解除，用户可能继续分心 |
| 用户用“主动放弃”绕过申请流程 | 申请原因和返回数据被架空 | 放弃前二次确认，明确将停止提醒且本次无奖励 | 当前不设冷静期；记录放弃及 30 分钟内重启，验证后再决定是否增加阻力 |
| 通知权限关闭 | 用户以为仍会被召回 | 仍允许开始和申请，但开始前清楚提示提醒不可用；60 分钟期限仍按时间计算 | 正常完成可结算，完成页标注“本次无提醒保护” |
| 用户用浏览器版或另一设备刷社媒 | 奖励与真实行为脱钩 | 奖励只命名为“无申请加分”，不宣称未碰手机 | 产品不监控其他设备，必须如实披露 |
| 空跑计时刷好感度 | 关系成长不代表真实学习 | 设置最短有效时长和单次上限的参数入口；不宣称验证学习成果 | 数值在行为测试前冻结 |
| 更换宠物后旧宠衰减 | 制造内疚和隐性惩罚 | 旧宠永久冻结并进入共同回忆 | 回忆文案仍需避免“抛弃”暗示 |
| 为看动画反复打开 App | 产品成为新干扰源 | 一次完成仅一次互动；无签到、信息流、重复领取 | 监测宠物页停留时间 |
| 签名存在但 entitlement 未获 | 工程能编译但核心不能真机运行 | entitlement、App ID、provisioning 独立门禁 | 未获批不得把模拟器界面当 P0 通过 |
| 通知成功但重锁失败 | 用户获得虚假安全感 | 重锁必须在真机以真实 Shield 恢复录屏证明 | 不能用通知投递或本地状态替代 |
| 复制同类宠物角色或界面 | 侵权、审核或品牌混淆 | 只使用原创角色、布局、文案和资产 | 正式资产需原创性审查 |

### 2.3 可证伪失败条件

P0 任一情况成立，立即停止完整开发并回到产品评审：

- 无法从 Shield 形成可理解的申请/返回路径；
- 无法解除本次专注中用户选择的全部受限 App；
- 用户返回后无法可靠重新施加全部限制；
- 系统真实限制状态与主 App 显示不一致；
- 必须影响本次用户选择范围之外的对象、使用私有 API 或依赖用户无法理解的设置技巧；
- 关键闭环只能在 Simulator 成功，无法在指定 iPhone 17 证明；
- entitlement 或审核边界使核心能力无法合法交付。

宠物层失败条件：首轮没有具体行为增量时允许一次受控优化；第二轮仍只能得到“可爱、喜欢、愿意试试”而没有开始、忍住、返回或主动复用证据，则停止批量资产和商业化投入。

## 3. Goals and Non-goals

### 3.1 产品目标

1. 降低考试学习期间对用户自选分心 App 的无目的使用；
2. 提高计划专注的完成率和必要使用后的返回率；
3. 让必要使用变成有原因、有计时、有原目标、有返回入口的行为；
4. 验证宠物是否促进开始、坚持或返回；
5. 形成无惩罚、低干扰、可删除、隐私优先的长期共同记录；
6. 为未来自由职业者场景保留结构，但不在 P1 同时扩大人群。

### 3.2 P1 范围

P1 是完整核心 App，而非单宠物展示 MVP，必须包括：

- 猫、狗、兔三选一；
- 三种角色方向和完整动作矩阵；
- 固定默认名、自定义命名及一次改名机会；
- 默认一次更换宠物机会；
- 好感度数值、关系阶段、共同回忆；
- 唯一目标、时长、限制 App、当前会话临时豁免；
- Family Controls/Shield/一次解除全部已选受限 App/10-30-60 分钟提醒/返回闭环；
- 完成后的喂食、洗澡或玩耍；
- 中断、重新开始和主动放弃；
- 英中双语、深色模式、降低动态效果、静音与基本可访问性；
- 本地历史、隐私设置和删除全部数据；
- 两类阈值待验证、各最多展示一次的纪念卡及系统保存/分享入口；
- 真实 iPhone 17 验收。

### 3.3 P1 明确不做

- AI 聊天、AI 宠物或生成式教练；
- 社交、好友、排行榜、公会、聊天和分享排行；
- 商店、IAP、付费宠物、付费造型和价格展示；
- 订阅、广告、抽卡、限时促销和付费加速；
- 房间系统、开放世界、剧情和多宠收藏；
- 签到、连续天数、登录奖励和每日强制任务；
- 锁屏 Widget、Shortcut、Action Button、Focus Mode 联动；
- 云账号、服务器、跨设备同步和网页后台；
- Android、Mac、Windows 和 Chrome 扩展；
- 医疗、ADHD 治疗或成瘾疗效承诺。

## 4. 用户体验与 User Stories

### 4.1 首次进入与认领

1. 用户先看到产品价值、权限用途和隐私边界；
2. 用户先输入一个示例学习目标；
3. 产品展示一次明确标注为演示的模拟 Shield 流程，让用户理解“被拦截—说明原因—返回目标”的价值；演示不得声称系统已经保护设备；
4. 用户理解核心流程后，再请求 Family Controls；通知权限在首次需要提醒保护的上下文中请求，不在首屏堆叠索权；
5. 用户从猫、狗、兔三张完整角色卡中选择一只；
6. 认领前清楚显示“一次更换机会”和“一次改名机会”；
7. 用户可使用固定默认名或输入自定义名字；默认名不随机；
8. 未授权 Family Controls 时可浏览产品说明，但不能显示“正在保护”；普通计时降级是否保留由 P0 后决定，不得静默冒充核心体验；
9. 权限被拒绝或撤销时，首页立即显示真实状态、影响和恢复指引。

### 4.2 创建专注

1. 输入本次唯一目标；
2. 选择 25、45、60 分钟或自定义时长；
3. 从系统选择希望限制的具体 App 或类别；
4. 可沿用上次选择；
5. 可为本次会话设置临时豁免，例如本次需要用 Reddit 查学习资料；
6. 开始前显示目标、时长、限制范围、通知状态和奖励规则；
7. 通知关闭时仍允许开始，但明确显示“必要使用提醒不可用”；
8. P1 不提供普通手动暂停。

通知关闭不改变正常完成的奖励资格；完成页必须标注“本次无提醒保护”。

如果用户进入必要使用，10/30/60 分钟通知不会送达，但通行窗口仍从产品发出解除命令并持久化可审计本地状态的时间开始计算。

### 4.3 专注中

- 始终显示：原目标、剩余专注时间、宠物陪伴状态；
- 宠物文案：`{宠物名}正在陪伴完成：{目标}`；
- 专注动画低频、可静态替代，不要求点击；
- 被选择的分心 App 受 Shield 保护；
- 误点受限 App 后直接返回，不算申请、不损失无申请加分；
- 锁屏或通知上的状态只有在系统允许可靠同步时才展示，不能承诺无法保持的一致性。

### 4.4 必要使用申请

- Shield 提供“返回专注”和“申请使用”入口；
- 理想路径是 Shield 打开主 App 的申请页；
- 申请提交前必须同时显示：原目标、本次将解除的全部受限 App、原因输入和 10/30/60 分钟规则；
- 主 App 同时提供预设原因和自定义原因；
- 预设原因至少包括：收取验证码、回复必要消息、查找学习资料、处理紧急事项；
- 自定义原因允许任意输入，不设置最低字符数；
- 宠物总是批准，不羞辱、不评判；
- 一次批准解除本次专注中用户选择的全部受限 App；不得扩大到本次选择范围之外；
- 申请次数不限；
- 单次通行窗口上限为 60 分钟；
- 产品发出解除全部已选受限 App 的命令并持久化可审计本地状态时开始计算通行窗口；P0 必须另外观察真实 Shield 是否解除，不得虚构系统完成回调；
- 10 分钟：温和召回并重新展示原目标；
- 30 分钟：提示“到通行满 1 小时仍未返回，本次专注将自动结束，也不会获得本次奖励”；
- 60 分钟：通知本次专注已经结束，本次不获得奖励；
- 三个时间点共用同一个通行窗口，不记录各 App 的独立前台使用时长；
- 必要使用期间暂停本次专注倒计时，不计入有效专注时间；这与“不提供普通手动暂停”是不同状态；
- 返回入口可以来自主 App 或通知按钮；用户直接锁屏不视为返回；
- 只有系统成功重新限制全部受限 App 后，才结束通行窗口并继续剩余专注时间；
- 用户在 60 分钟内返回并最终完成，仍获得基础奖励和一次互动，但不获得“无申请加分”；
- 60 分钟仍未返回时，本次专注自动结束、无奖励，受限 App 保持解除且不再发送返回提醒；
- 宠物等待采用低压力表达，例如“{宠物名}还在帮你守着：{目标}”，不得悲伤、焦虑或责备；
- 通知权限关闭时仍允许申请；提醒不可用，但 60 分钟期限继续按时间计算；

如果 P0 证明 Shield 无法可靠打开主 App，允许验证 Apple 官方能力范围内的替代导航，但不接受无法解除/重新限制本次完整选择集合、影响选择范围之外的对象、私有 API 或虚假状态。

### 4.5 完成、互动与奖励

- 正常完成：基础好感度；
- 全程没有通过产品申请通行：额外获得“无申请加分”；
- 申请后返回并完成：获得基础好感度，不获得无申请加分；
- 通知权限关闭但正常完成：按实际申请状态正常结算，完成页标注“本次无提醒保护”；
- 必要使用满 60 分钟未返回：本次专注结束，不获得基础奖励、无申请加分或完成互动；
- 完成后可在喂食、洗澡、玩耍中任选一个；
- 三类互动增加相同好感度，不建立饥饿、清洁、快乐等属性；
- 每次完成最多一次互动，不能储存、累积或重复领取；
- 用户可以跳过互动，不影响本次基础结算；
- 完成反馈和互动总时长应短，不把结算变成拖延。

### 4.6 中断、继续与放弃

- P1 不提供普通手动暂停；
- 用户主动放弃前必须二次确认，提示“解除后将不再提醒你返回原目标”；
- 用户确认放弃后立即解除本次 Shield；
- 放弃不获得本次基础奖励或无申请加分；
- 既有好感度、共同回忆和历史不减少；
- 宠物不失望、不受伤、不责备；
- 文案使用：`目标还在。下次回来，我们再一起开始。`；
- 用户下一次进入时正常欢迎，不显示失败、连续清零或补偿任务；
- 当前不设置放弃后的 15/30 分钟冷静期；先记录放弃和短时间重启行为，再决定是否需要增加返回阻力；
- 系统意外中断时提供“继续剩余时间”或“以同一目标重新开始”；
- 重启不会补发已经失去的无申请加分。
- 第一版记录放弃时间、30 分钟内是否重新开始以及放弃是否替代正式申请；不承诺记录放弃后的实际社媒前台时长。

### 4.7 历史、共同回忆与删除

- 首页显示简洁累计记录，不做复杂效率审判；
- 当前宠物档案显示名称、物种、好感度、关系阶段、共同完成次数和共同专注时长；
- 更换后的原宠进入“共同回忆”，保留名称、冻结好感度、关系阶段和共同记录；
- 回忆档案不得使用“被抛弃”“正在等你”“好感正在下降”等内疚文案；
- 默认不自动删除共同回忆；
- 自定义申请原因正文保存 30 天，到期只保留无正文的必要统计；
- 用户可查看申请历史中的申请次数、通行窗口总时长、是否返回和会话最终结果；不显示各 App 实际前台时长；
- 用户可删除单条申请原因或全部本地数据；
- “删除全部数据”须二次确认，并删除宠物、好感度、共同回忆、会话、原因和本地指标，返回首次认领流程；
- 删除全部数据会重置改名和换宠机会，这是用户删除全部积累后的自然结果，产品不通过隐藏标识阻止；
- P1 无账号、无云恢复，换机风险必须真实披露。

### 4.8 纪念卡传播假设

- 首批候选触发为“首次完成连续 2 小时专注”和“累计专注 10 小时”；两者可各展示一次；
- 以上数字只是待验证假设，不是固定产品标准，可根据真实使用调整；
- 纪念卡包含宠物形象、宠物名、里程碑和日期；默认不包含学习目标、申请原因或 App 名称；
- 用户可以关闭、保存或调用系统分享入口；不奖励分享、不反复提醒、不建立社交系统；
- 仅观察真实的保存动作和产品可确认的分享入口使用，不以“点击分享”冒充外部平台已经发布；
- 是否扩展正式传播功能只由后续真实保存和分享行为决定。

## 5. 宠物系统规格

### 5.1 一人一宠

- 同一时间只有一只当前宠物；
- P1 免费提供猫、狗、兔三种选择，但用户不是同时拥有三只；
- 宠物关系独立，不共享名字或好感度；
- 更换宠物不修改受限 App 设置，不删除全局专注历史。

### 5.2 性格与默认名字

| 宠物 | 性格方向 | 动作气质 | 默认名状态 |
|---|---|---|---|
| 猫 | 安静、松弛、略慵懒 | 克制、从容、小幅反应 | 美术方向确定后选择 |
| 狗 | 热情、温暖、有行动力 | 明快、积极但不过度兴奋 | 美术方向确定后选择 |
| 兔 | 温柔、轻盈、细腻 | 轻柔、谨慎、安静鼓励 | 美术方向确定后选择 |

默认名不随机，必须年轻化并与最终性格和视觉形象一致；具体名字、拼写和本地化显示在美术方向冻结时选择。三只宠物使用同一套功能文案模板，但通过动作、姿态和表情体现不同性格。

### 5.3 命名规则

- 认领时可直接使用默认名或输入自定义名字；
- 认领完成后，用户仅可再修改名字一次；
- 修改前提示剩余次数；
- 更换宠物后，新宠重新获得一次认领命名机会和一次后续改名机会；
- 原宠在共同回忆中保留冻结时的名字。

### 5.4 更换规则

- 默认仅允许更换一次宠物；
- 更换前二次确认，明确不可再次免费更换；
- 新宠好感度从 0 开始；
- 原宠好感度永久冻结，不衰减；
- 原宠进入共同回忆，可查看完整历史摘要；
- 更换不会触发哭泣、责备、生病、死亡或等待用户回去的表现；
- 未来付费宠物是否附带额外认领资格属于 P2 商业化规则，P1 不预设。

### 5.5 好感度与关系阶段

好感度来源：

- 完成有效专注；
- 无申请加分；
- 完成后一次可选互动。

好感度不来自：

- 打开 App；
- 连续登录；
- 通知召回；
- 购买；
- 重复点击；
- 离线等待。

关系阶段固定为：

1. 初次相遇；
2. 渐渐熟悉；
3. 彼此信赖；
4. 默契伙伴；
5. 长久陪伴。

P1 显示好感度数值和关系阶段，但以关系阶段为主要表达，精确数值作为次要信息。阶段阈值、时长换算、单次上限及互动加分在 P1 数值规格中参数化，不在 PRD 写死。P1 暂不根据阶段解锁新动作或内容。

### 5.6 动作资产矩阵

猫、狗、兔各自必须覆盖以下十个状态：

| 状态 | 触发 | 建议表现 | 降低动态效果 |
|---|---|---|---|
| 认领/初见 | 首次认领或更换完成 | 角色欢迎动作 | 静态主形象 |
| 待机 | 首页空闲 | 低频循环 | 静态待机帧 |
| 共同专注 | 专注进行中 | 学习桌旁安静陪伴 | 静态专注帧 |
| 批准使用 | 原因提交 | 简短确认 | 静态确认表情 |
| 通行提醒 | 10/30/60 分钟提醒 | 温和召回、后果提示或结束通知 | 静态提醒表情 |
| 完成 | 专注完成 | 克制庆祝 | 静态完成表情 |
| 欢迎回来 | 中断后再次进入 | 无责备欢迎 | 静态欢迎表情 |
| 喂食 | 完成后选择 | 一次短互动 | 首帧/结果帧 |
| 洗澡 | 完成后选择 | 一次短互动 | 首帧/结果帧 |
| 玩耍 | 完成后选择 | 一次短互动 | 首帧/结果帧 |

动作时间：

- 待机/专注：低频循环，无强提醒；
- 完成/欢迎回来：2–4 秒；
- 喂食/洗澡/玩耍：3–5 秒；
- 批准/提醒：1–2 秒；
- 开启降低动态效果时全部提供静态替代。

### 5.7 视觉方向门禁

正式批量生产前按以下顺序：

1. 生成三套完整视觉方向，每套同时包含猫、狗、兔；
2. 每套包含角色比例、性格差异、简单学习桌场景、首页/专注页粗略应用、低饱和暖色板和深色模式示意；
3. 用户选择整体方向与角色比例；
4. 选一只宠物测试帧动画、矢量或局部动画三种实现路线中的最小代表动作；
5. P0 技术闭环通过、美术方向确定且非开发行为测试出现初步正向信号后，再决定正式动画管线并批量制作三只宠物的全部动作。

视觉原则：

- 整体低饱和、温暖、安静；
- 三个物种可有识别色，但不能破坏统一品牌；
- 支持深色模式；
- 不复制 Finch、Focus Friend、Forest、Study Bunny 等角色轮廓、配色、房间布局或动作构图；
- P0 不制作正式宠物资产。
- P0 FAIL 时，已完成的视觉方向图保留为研究参考，但停止批量资产和 P1；是否另作他用必须重新进行产品决策。

### 5.8 声音与触觉

- 默认静音；
- 用户可选择开启宠物短音效和触觉；
- 系统通知使用用户允许的通知声音；
- 图书馆场景下关闭声音不影响理解；
- 关键状态不得只通过声音、颜色或宠物表情表达。

## 7. 核心状态机

```text
IDLE
  → CONFIGURING
  → FOCUSING
      → SHIELD_PRESENTED
          → FOCUSING                     # 直接返回，保持无申请加分资格
          → REQUESTING_USE
              → ACCESS_WINDOW_ACTIVE      # 全部已选受限 App 解除；专注计时暂停
                  → FOCUSING_INTERRUPTED  # 60 分钟内返回、全部重锁、继续剩余时间
                  → ACCESS_TIMED_OUT      # 60 分钟未返回；会话结束、App 保持解除
      → COMPLETED_NO_REQUEST
      → COMPLETED_WITH_REQUEST
      → ABANDONED
      → RECOVERY_REQUIRED                 # 系统终止/状态不确定
```

状态规则：

- 不存在用户可操作的普通 `PAUSED`；
- `ACCESS_WINDOW_ACTIVE` 是必要使用状态，不计入专注时间；以产品发出解除命令并成功持久化本地可审计状态的时刻为起点；真实 Shield 解除状态另行观察；
- 直接锁屏不构成返回；只有主 App/通知入口触发且系统成功重新限制全部对象后才恢复专注；
- `ACCESS_TIMED_OUT`：本次无奖励、停止提醒、App 保持解除；用户界面不使用羞辱性的“失败”表达；
- 60 分钟截止时间是持久化的逻辑期限；通知投递和后台执行不是状态权威。若 App 当时未运行，下一次主 App/Extension 可执行时必须先按截止时间校正为 `ACCESS_TIMED_OUT`；
- `COMPLETED_NO_REQUEST`：基础好感度＋无申请加分＋一次可选互动；
- `COMPLETED_WITH_REQUEST`：基础好感度＋一次可选互动；
- `ABANDONED`：二次确认后立即解除 Shield，本次无奖励；
- `RECOVERY_REQUIRED`：不得显示保护成功；先核真实权限和限制状态，再允许恢复或结束；
- 所有限制和解除命令必须幂等；重复回调不得重复奖励；
- 系统状态不确定时，奖励采取保守策略且向用户显示真实故障，不使用假成功。

## 8. P0 技术验证规格

### 8.1 P0 唯一目标

只回答这一闭环是否能在 Apple 官方能力范围内可靠实现：

> Shield 申请 → 主 App 填写原因 → 解除本次全部已选受限 App → 10/30/60 分钟统一提醒 → 60 分钟内返回后重新限制全部对象。

P0 不验证宠物吸引力、留存、商业化或正式视觉，也不制作正式宠物资产。
P0 不要求记录 Shield 展示次数或“直接返回”次数；只验证核心限制闭环及产品自身明确发生的申请、返回、放弃、完成和超时事件。

### 8.2 P0 Target 拓扑

P0 建议包含：

1. 主 App；
2. Device Activity Monitor Extension；
3. Shield Configuration Extension；
4. Shield Action Extension。

P0 初期不创建 Device Activity Report Extension，除非后续明确需要 Screen Time 报表能力。

### 8.3 App Group 最小共享状态

P0 只保存跨 Target 必需的轻量状态：

- schema/version；
- session ID；
- 会话状态与幂等 generation；
- 本次专注选择的完整限制集合及其 opaque tokens；
- 触发申请的入口 token（仅用于上下文，不缩小解除范围）；
- 申请原因类型引用；
- 通行窗口开始时间和 60 分钟截止时间；
- 10/30/60 分钟提醒计划标识；
- 重锁命令/结果码；
- 最近一次可验证状态和错误码。

自定义原因正文不进入 Extension 共享轻量状态，除非实现确有必要且完成隐私评审；主 App 本地存储正文并按 30 天规则删除。

### 8.4 P0 理想路径与允许降级

理想路径：

- Shield Action 能将用户送到主 App；
- 主 App 提供预设原因和自定义原因；
- 申请页显示原目标、全部解除范围和提醒规则；
- 解除本次专注中用户选择的全部受限 App；
- 从解除命令写入可审计本地状态开始统一计算 10/30/60 分钟，并单独核对真实 Shield；
- 用户返回后重新施加全部 Shield；
- 60 分钟未返回时结束专注、停止提醒并保持 App 解除。

P0 不得预设 `stopMonitoring` 或等价调用存在“解除完成”回调。若 Apple 当前公开 API 无法提供完成回调，时间锚点使用本地命令/状态时间，系统结果则通过真机可观察行为单独取证。

允许验证的降级：

- Shield 仅提供有限按钮，原因输入放在主 App；
- 原因预设与自定义的呈现顺序因官方框架限制调整；
- 通知受系统权限、专注模式和调度影响，产品明确显示能力状态。

不可接受：

- 影响本次用户选择范围之外的对象；
- 用户返回后无法可靠重新限制全部对象；
- 用主 App 自己的布尔值冒充系统 Shield 状态；
- 使用私有 API、VPN 劫持、辅助功能滥用或屏幕读取；
- 只在 Simulator 通过；
- P0 失败后静默改成普通计时器并继续宣布核心产品成立。

### 8.5 真机证据矩阵

必须在指定真实 iPhone 17 上逐项记录 PASS/FAIL 和录屏：

1. 授权、拒绝、撤权、重新授权；
2. 选择单个 App 和类别；
3. Shield 展示与直接返回的体验行为；不要求记录展示/返回次数；
4. Shield 到主 App 申请页；
5. 申请页同时显示原目标、解除范围、原因和 10/30/60 规则；
6. 预设原因、自定义原因和任意字符输入；
7. 解除本次专注中用户选择的全部受限 App，不影响选择范围之外的对象；
8. 从解除命令写入可审计本地状态时开始通行计时，并分别记录命令时间与首次观察到真实 Shield 解除的时间；
9. 10 分钟温和召回、30 分钟超时警示、60 分钟结束通知；
10. 通知权限关闭时仍可开始/申请，显示提醒不可用且 60 分钟期限继续计算；

12. 返回后全部对象必须真实重锁，只有全部成功后才恢复专注计时：
    - 在返回命令后的 0 秒、30 秒、1 分钟和 5 分钟观察；
    - 记录首次可见真实 Shield 恢复时间；
    - 本轮先收集事实，不预设可接受延迟阈值；最终无法恢复仍为 FAIL；
13. 60 分钟未返回时结束专注、不给奖励、停止提醒且 App 保持解除；
14. 主动放弃二次确认后立即解除 Shield；
15. App 前后台、锁屏、系统终止、设备重启后的状态；
16. 修改系统时间/时区后不得错误结算；
17. token 失效后的真实提示；
18. 与另一个 Screen Time App 并存时的可观察行为；
19. 重复回调、快速点击和恢复流程不得重复奖励或显示假状态。

## 11. 测试与验收

### 11.1 技术验收

按第 8 章 P0 真机矩阵执行。P0 结论只有：

- PASS：核心闭环逐项通过；
- FAIL：存在不可接受项；
- BLOCKED：entitlement、签名或设备等外部条件尚未满足。

不得把 BLOCKED 写成 PASS，也不得以部分路径成功宣布技术绿灯。

### 11.2 P1 功能验收

- 三只宠物核心能力等价；
- 三只宠物全部覆盖十项动作；
- 默认名固定且与性格一致；
- 除“删除全部数据并丢失全部积累”外，改名次数、换宠次数不可被普通操作绕过；
- 原宠永久冻结并进入可查看共同回忆；
- 删除全部数据真实清除并回到认领；
- 三类完成互动奖励完全一致；
- 申请后完成没有无申请加分；
- 误点直接返回不损失加分资格；
- 主动放弃二次确认后立即解除 Shield 且无本次奖励；
- 必要使用解除全部已选受限 App，10/30/60 分钟使用同一通行窗口；
- 用户返回时必须全部重锁成功后才能继续专注；
- 60 分钟超时结束会话、无奖励、停止提醒且 App 保持解除；
- 通知关闭时不显示虚假提醒承诺，正常完成仍按实际申请状态结算并标注“本次无提醒保护”；
- 申请历史可查看次数、窗口总时长、是否返回和最终结果；
- 两类候选纪念卡各最多展示一次，不包含目标、原因或 App 名称，不奖励分享；
- 英中切换、深色模式、VoiceOver、动态字体和降低动态效果可完成核心路径。

### 11.3 行为验证位置

非开发行为验证与 P0 可以并行，但不得因此批量制作正式宠物资产。可使用故事板、静态角色方向、人工挑战和可说明的演示测试：

- 用户是否更容易开始；
- 在冲动打开社媒时是否产生停顿；
- 必要使用后是否更容易返回；
- 第 7 天是否无提醒主动复用；
- 宠物是否提供具体行为增量，而不只是“可爱”；
- 一次解除全部已选受限 App、60 分钟通行窗口是否被系统性滥用；
- 主动放弃是否替代正式申请；
- 纪念卡是否产生真实保存或分享入口使用，而不是口头“愿意分享”；
- 权限说明是否引发拒绝、撤权或卸载。

具体成功数值暂不作为当前制作 P0/视觉方向的前置决定；在真实用户验证开始前另行冻结测量协议。第一版只使用产品自身明确发生的正式申请、返回、完成、放弃、超时和纪念卡动作；不要求 Shield 展示/直接返回计数。更细的屏幕使用测量等待真实用户使用后再决定。

### 11.4 第一轮失败后的唯一优化机会

若宠物没有明确增量：

1. 只允许优化宠物与目标、提醒、返回三处核心连接；
2. 不增加 AI、社交、签到、房间、剧情和更多宠物；
3. 不改变 Family Controls 技术范围；
4. 重新测试一次；
5. 仍无行为证据则停止批量内容和商业化，不用“用户说可爱”替代。

### 16.3 当前最大未验证风险

1. Apple 是否允许理想的 Shield→主 App→解除全部已选受限 App→返回统一重锁闭环；
2. Family Controls entitlement 是否获批；
3. 一次解除全部已选受限 App、申请次数不限是否使原因停顿逐渐失效；
4. 10/30/60 分钟提醒是否足以召回，以及超时后保持解除是否放大偏航；
5. 宠物是否产生行为增量，而不只是视觉偏好；
6. 三宠十项动作的成本、一致性和性能；
7. 无成长节点、无签到、无惩罚时，关系阶段是否足够支撑复用；
8. 英中双语和英语文案是否符合学生真实语感；
9. 目标学生设备系统版本是否与当前 iOS 27 真机环境存在差距；
10. 一人一宠、一次改名和一次更换是否产生不必要的选择焦虑；
11. 候选纪念卡是否带来真实保存/分享行为，还是仅增加一次视觉内容；
12. 主动放弃是否成为比正式申请更容易的旁路。
